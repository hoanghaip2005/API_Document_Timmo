API Documentation

Timmo Backend API v1

Tài liệu private API cho owner, employee, account, shop, service, attendance, settlement và report. Layout viết lại theo kiểu sidebar + endpoint cards giống các trang API docs hiện đại, bám theo source backend hiện tại.

Gọi API

Business API nằm dưới /api/v1. Monitoring được mount trước App Check để Cloud Run probe được gọi độc lập.

Quy ước dữ liệu

Nhóm Quy ước
Money Backend shop tạo mới dùng currency: "EUR". Field money là number theo money scale backend. UI có thể hiển thị ký hiệu đ.
Ngày công workDate format YYYY-MM-DD. Business day có thể phụ thuộc settlementCutoffTime.
Giờ trong ngày startTime, endTime là số phút trong ngày; endTime > startTime.
Content-Type Write JSON dùng application/json. Avatar/service image dùng JSON parser 8MB.
Cache GET có thể trả ETag, X-Cache, private cache ngắn. Client invalidate cache sau write.

Settlement

Rule hiện tại: discountAllocationMethod = "revenue_share", default ownerDiscountCoverageRate = 50. Nhân viên hourly/lương cứng không chịu giảm giá; phần của họ chuyển sang chủ chịu.
Bước Công thức
Chủ chịu cơ bản ownerBaseDiscount = totalDiscount * ownerDiscountCoverageRate / 100
Pool nhân viên employeePool = totalDiscount - ownerBaseDiscount
Chia pool employeePool * employee.totalRevenue / totalRevenue theo tổng doanh thu cả ngày.
Commission Ghi discountAllocated, trừ vào employeeEarning.
Hourly/fixed Ghi ownerDiscountSupported, cộng vào chủ chịu.
Tổng chủ chịu totalOwnerDiscount = ownerBaseDiscount + sum(ownerDiscountSupported)

Contract reference

Phần này dùng như tài liệu tích hợp nhanh: header, success body, lỗi cần xử lý, field canonical.

Header Áp dụng Chi tiết
Authorization Hầu hết API Bearer <accessToken>. Riêng signin/change-password dùng Firebase ID token.
Content-Type Write JSON application/json.
X-Firebase-AppCheck Production Bắt buộc theo môi trường production. Monitoring route không cần.
X-Idempotency-Key POST/PATCH/DELETE Nên dùng key ổn định theo hành động; replay thành công trả X-Idempotency-Replayed.
If-None-Match GET cacheable Dùng với ETag nếu client tự quản cache.

Success envelope

API không bọc chung trong { data }. Mỗi route trả object domain trực tiếp: signin trả session, settlement list trả { branchId, items }, close-day trả { workDate, items }.

Error envelope

Error luôn có type và message. Một số lỗi nghiệp vụ có field bổ sung, ví dụ close-day incomplete có invalidAttendanceIds.

close-day-incomplete.json 
{
  "type": "/employee/attendance-incomplete",
  "message": "Some attendance entries are missing services, assignees, or full allocation",
  "invalidAttendanceIds": ["attendance_1", "attendance_2"]
}
HTTP Client xử lý
400 Sửa request/body/query, không retry nguyên trạng.
401 Refresh token hoặc buộc đăng nhập lại.
403 Không retry; role/scope không đủ quyền.
409 Refresh dữ liệu màn hiện tại rồi hiển thị lý do.
429 Chờ theo Retry-After, không spam retry.

Business flows

Owner settlement V2

  1. Owner chọn store ở Home; /daily-settlement dùng branch đó, không chọn store lại.
  2. List gọi GET /employee/session/settlements trong tháng hiện tại, tối đa 31 ngày.
  3. Ngày ready khi có attendance, tất cả đã closed, không incomplete.
  4. Detail gọi GET /employee/session/settlement-preview; backend preview là source tiền duy nhất.
  5. Owner chỉ chỉnh ownerDiscountCoverageRate 0/50/100; không chọn method, không chọn nhân viên chịu discount.
  6. Confirm gọi POST /employee/session/close. Sau close detail read-only, list dùng totalOwnerNetAfterDiscount làm số chủ thực nhận.

Employee close-day

  1. Employee portal guard gọi GET /employee/me/bootstrap.
  2. Nhân viên tạo attendance bằng POST /employee/attendance; nếu có chia việc thì assignee percentage phải đủ rule.
  3. Nhân viên bấm Chốt ngày, gọi POST /employee/me/attendance/close-day.
  4. Backend đóng all-or-nothing toàn bộ attendance trong ngày mà employee được assign.
  5. Nếu ngày đã owner chốt sổ, backend trả locked; UI phải refresh cache và không cho sửa.

Service group inline

  1. Màn tạo service load /shop/service/bootstrap để có group hiện có.
  2. User chọn group từ dropdown; nếu chưa có thì chọn tạo nhóm mới inline.
  3. Submit dùng cùng POST /shop/service, gửi groupService; không cần màn tạo group riêng.

Owner chốt sổ

  1. GET /shop/branch hoặc branch từ bootstrap.
  2. GET /employee/session/settlements?branchId=&fromWorkDate=&toWorkDate= để render list.
  3. GET /employee/session/settlement-preview?branchId=&workDate=&ownerDiscountCoverageRate=50 để render detail.
  4. POST /employee/session/close khi tất cả attendance ready.

Employee chốt ngày

  1. GET /employee/me/bootstrap để lấy assignment và attendance.
  2. Nhân viên tạo/sửa attendance trong ngày.
  3. POST /employee/me/attendance/close-day một lần cho ngày đó.
  4. Refresh portal cache; card chuyển trạng thái đã đóng.
