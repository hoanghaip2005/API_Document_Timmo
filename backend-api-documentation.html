Nail Salon Management System Backend - API Documentation

Ngày cập nhật: 2026-06-05

Tài liệu này mô tả các API đang được mount trong backend TypeScript/Express hiện tại. Nội dung được tổng hợp lại từ src/app.ts, các router trong src/business/*/index.ts, auth/session helper, response helper, middleware auth/cache/idempotency/rate-limit và đối chiếu bằng GitNexus. Bố cục tham khảo phong cách tài liệu API theo nhóm endpoint, bảng tham số, response mẫu và mã lỗi như Nhanh.vn API v3 và Zalo Developers Social API.

1. Phạm vi

  • Base path chính: {{baseUrl}}/api/v1.
  • Tổng số endpoint /api/v1 đang được mount: 55 endpoint.
  • Root endpoint ngoài API: GET /.
  • Tài liệu chỉ ghi nhận route thật sự được đăng ký trong src/app.ts và router index. File handler tồn tại nhưng không mount route sẽ không được coi là API public.
  • Auth hiện có accessToken và refreshToken. jwtToken vẫn được giữ như alias cũ của accessToken để HRM/module cũ không vỡ contract.
  • Weekly report hiện tại chỉ mount 3 route: list, detail, generate. Các route regenerate/delete từng xuất hiện trong tài liệu protocol cũ không có trong weekly-report-index.ts hiện tại.

4. Format lỗi chung

Mọi lỗi public trả JSON:

{
  "type": "/namespace/error-code",
  "message": "Human readable message"
}

Các lỗi chung:

  • 401 API Header Error: thiếu Authorization, sai scheme Bearer, access token không hợp lệ hoặc token đã revoke.
  • 401 /auth/token-expired: access token backend hết hạn.
  • 401 /auth/invalid-refresh-token, 401 /auth/refresh-token-expired, 401 /auth/refresh-token-revoked: lỗi khi gọi refresh token.
  • 401 /auth/app-check-required, 401 /auth/app-check-invalid: App Check bật required.
  • 400 /request/invalid-idempotency-key: idempotency key dài hơn 200 ký tự.
  • 409 /request/idempotency-conflict: cùng key nhưng body khác.
  • 413 /request/payload-too-large: payload vượt giới hạn parser.
  • 415 /request/unsupported-media-type: body không phải JSON/form-urlencoded.
  • 429 /request/rate-limit: vượt rate limit.
  • 404 /request/not-found: route không tồn tại.
  • 500 /internal-server-error: lỗi không được handler chuyển thành public business error.

Token lifecycle cho HRM/module đấu nối: GitHub Pages chỉ host tài liệu HTML, không cấp token và không được lưu token thật. 5.5. Attendance input

Backend hỗ trợ 2 body format cho create/update attendance.

Legacy format:

{
  "workDate": "2026-06-01",
  "branchId": "branch-1",
  "branchName": "Main Store",
  "startTime": 540,
  "endTime": 600,
  "customerName": "Linh",
  "service": {
    "mode": "existing",
    "serviceId": "service-1",
    "name": "Gel Manicure",
    "category": "manicure",
    "price": 35,
    "duration": 60
  },
  "assignees": [
    { "employeeUserId": "employees-1", "percentage": 100 }
  ],
  "discount": {
    "allocationMode": "attendance",
    "type": "amount",
    "value": 5,
    "splitMode": "all_assignees",
    "ownerCoverageRate": 0
  }
}

Legacy rules:

  • Bắt buộc workDate, branchId, branchName, startTime, endTime, assignees.
  • Cung cấp đúng một trong service hoặc services length 1.
  • endTime phải lớn hơn startTime.
  • assignees tối đa 20, không trùng employeeUserId.
  • Nếu một assignee có percentage, tất cả assignee phải có percentage và tổng không vượt 100.
  • discount.type: amount hoặc percentage; splitMode: all_assignees hoặc selected_assignees; ownerCoverageRate: 0, 50, 100.

Frontend format:

{
  "date": "2026-06-01T09:00:00.000Z",
  "endDate": "2026-06-01T10:00:00.000Z",
  "branchId": "branch-1",
  "customerName": "Linh",
  "services": [
    {
      "id": "line-1",
      "sourceServiceId": "service-1",
      "name": "Gel Manicure",
      "category": "manicure",
      "price": 35,
      "duration": 60,
      "employees": [
        { "employeeId": "employees-1", "percentage": 100 }
      ]
    }
  ],
  "discountAmount": 5
}

Frontend rules:

  • Bắt buộc date, services, và một trong branchId hoặc storeId.
  • services: 1..50 item.
  • Mỗi service cần id, name, price. category, sourceServiceId, duration, durationMin, durationMax, time, imageUrls, images, amount optional.
  • employees: tối đa 20 item, dùng employeeId; có thể gửi percentage, shareAmount.
  • Có thể dùng createdAt/endDate hoặc startTimestamp/endTimestamp.
  • Nếu service không có employees, backend có thể default assignee là creator nếu creator là employee active trong branch.

8. Ghi chú kiểm thử contract

  • Với endpoint dùng ETag, test nên gọi lần 1 lấy ETag, lần 2 gửi If-None-Match, kỳ vọng 304 nếu dữ liệu không đổi.
  • Với mutating endpoint, test idempotency nên gửi cùng X-Idempotency-Key và cùng body hai lần, kỳ vọng lần replay có X-Idempotency-Replayed: true; gửi cùng key khác body kỳ vọng 409 /request/idempotency-conflict.
  • HRM/module đấu nối lấy token từ backend, không lấy từ GitHub Pages. Flow chuẩn: Firebase ID token -> /auth/signin -> dùng accessToken gọi API -> dùng refreshToken gọi /auth/refresh-token khi access token expired.
  • Không gọi /auth/signin cho từng API business. Signin hiện tốn khoảng 1 Firestore read + 1 write lastLoginAt; verify access token và refresh token không làm phát sinh Firestore reads.
  • jwtToken vẫn là alias legacy của accessToken. Không xóa field này nếu HRM/module cũ còn đọc.
  • Attendance nên test cả payload legacy và frontend vì backend vẫn hỗ trợ cả hai contract.
  • Weekly report list không tự generate missing week; detail với generateIfMissing=true, owner report summaryOnly và monthly salary optimized mới có thể generate/read weekly-report.
  • Các lỗi từ repository nếu document không tồn tại có thể đi qua error handler generic hoặc firestore error mapper tùy repository; tài liệu trên liệt kê lỗi public mà handler chủ động trả.
